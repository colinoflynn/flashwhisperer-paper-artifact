### Where the line offset came from

DERIVED, not copied. The flash read width is 8 x 16-bit words -- measured, because the latch cost steps at delta 8 and nowhere else -- and SBOX_P packs 2 byte entries per 16-bit word, so a row holds 8 x 2 = 16 entries and byte indices collide iff (i>>4) == (j>>4), giving line_shift 4. 0x088000 / 8 is exact, so line_off 0. That is the same 4 an ARM byte S-box gets behind a 16-byte line, but for two independent reasons that happen to multiply to 16 -- the check that it is a derivation is that the UNPACKED SBOX_U on this same part would be line_shift 3.
