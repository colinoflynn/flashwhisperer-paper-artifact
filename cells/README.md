# cells/

*🤖WARNING🤖: This file LLM generated and may read oddly. Will eventually be human-edited for that real-life touch and typos.*

One entry per result cell in the paper's cross-part table, where a cell is one
`(part, configuration, field)` triple and `field` is the byte S-box, the
compact T-table or the four-table build. Not one per configuration: the table
renders three result fields per configuration row, and a configuration whose
S-box cell has an artifact and whose T-table cells do not is two thirds
uncovered.

```bash
python tools/make_cells.py --research ../../flash-accelerator-tests
python tools/make_cells.py --research ... --check    # regenerate and diff
python tools/make_cells.py --research ... --pages    # the per-cell markdown
```

`cells.json` is derived and `tools/make_cells.py` is the derivation, which is
deliberate. The triage fragments it reads land in batches, and a hand-copied
register goes stale between two of them. Two inputs, both in the research tree:
`research/reference/cross_part_table.json` for the claims and the `repro`
blocks, and `research/reference/repro/<part>.json` for the verdict on every
cell that has no block, which is where `recapture` and `drop` live.

## What a cell carries

The claim text as the table prints it, the verdict, the dossier that holds the
evidence, whether the paper's one-page render includes the row, and for a cell
with an artifact the whole `repro` block: the capture, the observable, the
rungs, the pair sets, `line_shift`, `line_off`, `ct_adjacent`, `expect`, and
the prose saying where the line offset came from and why that capture backs
this cell.

Three fields have a spelling problem worth knowing about before writing
anything that reads this file.

`expect` appears as an integer, as a string with a thousands space (`"6 250"`),
and as prose (`"0/16 at 275 000"`). The parsed value is in `expect_n` and the
original stays in `expect`, because the prose carries a claim that the integer
would invert: reading the first number out of `"0/16 at 275 000"` would score a
null cell as a break at zero traces.

`ct_adjacent` appears as the string `"both"`, meaning both last-round
adjacencies were swept at triage. `archive.ladder` takes a boolean and every
non-empty string is truthy, so handing `"both"` through scores ciphertext
adjacency alone, which on a byte-S-box final round is a clean 0/16.
`reproduce.py` runs both and reports which won.

`capture` is a path on all but one cell. That one names eight files summed with
`ladder.py --concat` in a sentence, so `capture_form` is computed beside it and
says `path`, `concat` (with the file list expanded) or `prose`. A tool that
calls `os.path.exists` on the sentence reports the cell missing.

## The verdicts

| | |
|---|---|
| `block` | a capture with per-trace data and a geometry that recovers. `reproduce.py` replays it |
| `flat` | the claim is that the cell is constant, so there is nothing to recover. The artifact is the capture and its distinct count, and `n` goes with it: one distinct cycle count in 2 000 traces is a much weaker claim than one in 400 000 |
| `recapture` | the data on disk cannot support the claim. The cell says which board, which cipher, how many traces and what is missing. A normal outcome rather than a failure: several campaigns recorded summaries rather than traces, and a new capture beats an argument about an old one |
| `drop` | the cell should not be in the table, with a reason that stands on its own |

`cells.json` is one of the places allowed to count. For the tally run
`python tools/verify.py`, and for the gaps with their reasons
`python tools/reproduce.py --show-gaps`.

## The per-cell pages

`<part>/<cell>.md` is generated by `make_cells.py --pages` and is not
hand-edited. The prose in them is the research tree's own, carried across so a
reader can see what a cell claims and what was recorded about it without
needing that tree.
