### Where the line offset came from

DERIVED, and the derivation is the point on these cells. DATASHEETS.md *Measured on this bench* gives this part a **64-bit (8 B) flash read width**; the 32 B in the adjacent column is the ART cache conflict period, and the roster records that scoring that instead costs 4.5x on this part. So one-byte entries in an 8-byte row give **line_shift 3**. **But the table the attack partitions is not Te0.** Both `aes_ttable_encrypt` and `aes_ttable1_encrypt_nr` use Te0..Te3 for rounds 1-9 only; the last round has no MixColumns and both fall back to the one-byte `SBOX` (rigs/fw_l4_aes/aes.c). A last-round attack scores the last round's reads, so the row map is SBOX's and line_off is SBOX mod 8, which is 0 on all three images. Te0's own geometry would be line_shift 1 and is the wrong model here. line_shift 5 was scored as the cross-check this fragment's contract asks for, and line_shift 1 as a sensitivity check: the predictor is SINV either way, so 1 is a finer partition of the same table rather than a Te0 model.
