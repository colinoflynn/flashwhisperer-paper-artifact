### Where the line offset came from

DERIVED, not swept: line_off 0 and line_shift 3. The G474's flash read word is 8 bytes and every build's final round reads the 256 B byte S-box, so entries are one byte -- the same derivation the covered T-table blocks on this part use from SBOX 0x08001f00 mod 8 = 0 in rigs/fw_g4. For rigs/fw_g4_ctguard the base is 8-aligned under both link scripts: link_pad.ld puts SBOX at 0x08000770 (stated in stm32g474_latency0.md §4f) and link.ld puts aes.o's .rodata at 0x08002df0 per rigs/fw_g4_ctguard/fw.map, so the offset is 0 either way and does not depend on which image this capture ran. For rigs/fw_g4_align at SBOX_OFF = 0 it is 0 by construction: tables.h pads with a 32-byte-aligned aestab_pad[32 + SBOX_OFF] so SBOX lands at exactly SBOX_OFF mod 32, read out of the source rather than off a .map.
